## 6. Backend — Deep Dive

### 6.1 Entry Point & App Setup

**`backend/src/server.ts`**
- Loads `dotenv` first, then imports app and `dbConnect`
- Calls `dbConnect()`, then starts Express on `process.env.PORT` (default 5000)
- Exits with code 1 on database connection failure

**`backend/src/app.ts`**
- CORS: allows `process.env.CLIENT_URL`, credentials: true
- Body parsers: `express.json()`, `express.urlencoded({ extended: true })`
- Static files: `/api/v1/uploads` → `./uploads`
- Route mounts:
  ```
  /api/v1/products   → product.routes.ts
  /api/v1/user       → auth.routes.ts
  /api/v1/orders     → order.routes.ts
  /api/v1/wishlist   → wishlist.routes.ts
  /api/v1/otp        → otp.routes.ts
  /api/v1/contact    → contact.routes.ts
  /api/v1/categories → category.routes.ts
  ```
- 404 handler for unmatched routes
- Global error handler (handles Multer errors too)

**`backend/src/constants.ts`**
```typescript
export const DB_NAME = "MyStartUp";
```

---

### 6.2 Database Connection

**`backend/src/db/index.ts`**
- Reads `MONGODB_URI` from env (throws if missing)
- `mongoose.connect(uri)` — returns connection instance
- Used in `server.ts` before starting the HTTP server

> MongoDB Cluster: `kaizen-art-craft-0` on AWS Mumbai (ap-south-1), MongoDB 8.0, replica set.
> Uses standard URI (not SRV) for mobile hotspot compatibility.

### 6.4 Controllers

#### `auth.controller.ts`

| Function | What it does |
|---|---|
| `generateTokens(userId, role)` | Returns `{ accessToken, refreshToken }` — JWT signed with respective secrets |
| `signup(req, res)` | Validates body, checks duplicate email/username, bcrypt-hashes password, creates User, returns tokens |
| `login(req, res)` | Validates email+password, bcrypt compares, sets refreshToken as HttpOnly cookie, returns accessToken |
| `refresh(req, res)` | Reads refresh token from cookie, verifies it, issues new accessToken |
| `logout(req, res)` | Clears the `refreshToken` cookie |
| `getProfile(req, res)` | Returns `req.user` data without password |
| `updateProfile(req, res)` | Updates `fullName` and `phone` on authenticated user |
| `getAllUsers(req, res)` | Admin only — returns all users without passwords |

#### `product.controller.ts`

| Function | What it does |
|---|---|
| `createProduct(req, res)` | Parses multipart form, validates required fields, calculates discount, saves product with image paths |
| `updateProduct(req, res)` | Partial update — handles text/numbers/arrays/new images; recalculates discount if price changes |
| `deleteProduct(req, res)` | Soft delete: sets `isActive: false` |
| `getProducts(req, res)` | Filtered query: `?category`, `?collectionId`, `?featured`, `?bestSeller`, `?search`, `?page`, `?limit` |
| `getProductById(req, res)` | Finds by `_id`, populates `reviews.userId` with user name/email |
| `getProductBySlug(req, res)` | Finds by slug (SEO route) |
| `addReview(req, res)` | Authenticated; validates rating 1–5; prevents duplicate reviews; calls `calculateRatings()` |
| `checkAvailability(req, res)` | Checks if provided `pinCode` is in `serviceablePinCodes` array |

#### `cart.controller.ts`

| Function | What it does |
|---|---|
| `addToCart(req, res)` | Finds user, looks for existing cart item with same productId — increments quantity if found, pushes new item if not |

#### `order.controller.ts`

| Function | What it does |
|---|---|
| `checkout(req, res)` | Creates Order from `req.user.cart`, clears user's cart, returns created order |
| `getMyOrders(req, res)` | Returns orders for `req.user.id`, sorted by `createdAt` descending |
| `getAllOrders(req, res)` | Admin only — all orders, populates `userId` with name/email |

#### `category.controller.ts`

| Function | What it does |
|---|---|
| `getAllCategories(req, res)` | Returns all Collection documents |
| `getProductsByCategory(req, res)` | Filters products by `req.params.id` (uses `category` field) |

> **Bug:** `getProductsByCategory` filters by `category` string field, but route param is likely a collection `_id`. Verify intent when fixing.

#### `otp.controller.ts`

| Function | What it does |
|---|---|
| `sendOTP(req, res)` | Generates 6-digit OTP, checks hourly send limit (max 5), saves OTP to DB, **logs to console** (TODO: SMS provider) |
| `verifySignupOTP(req, res)` | Validates OTP + attempts; creates User with phone-based signup; returns tokens |
| `verifyLoginOTP(req, res)` | Validates OTP; authenticates User by phone; returns tokens |

**OTP Logic constants (from `utils/otp.ts`):**
```typescript
OTP_EXPIRY_MINUTES  = 5
MAX_VERIFY_ATTEMPTS = 3
MAX_OTP_PER_HOUR    = 5
```

### 6.6 Middleware

#### `auth.middleware.ts`

**`protect`**
1. Reads `Authorization: Bearer <token>` header
2. Verifies with `JWT_SECRET`
3. Attaches `{ id, role }` to `req.user`
4. Returns 401 if missing or invalid

**`isAdmin`**
- Checks `req.user.role === "admin"`
- Returns 403 if not admin

```typescript
storage: diskStorage({

})
```

## 9. Authentication Flow

```
1. User calls POST /user/login or POST /otp/verify-login
   ↓
2. Backend generates:
   - accessToken  (JWT, 15min, JWT_SECRET)
   - refreshToken (JWT, 7d, JWT_REFRESH_SECRET)
   ↓
3. Response:
   - Body:   { accessToken, user }
   - Cookie: refreshToken (HttpOnly, Secure, SameSite=Strict)
   ↓
4. Frontend stores accessToken in localStorage
   Axios interceptor attaches it to all future requests as:
   Authorization: Bearer <accessToken>
   ↓
5. When accessToken expires:
   - Call POST /user/refresh (cookie sent automatically)
   - Receive new accessToken
   ↓
6. Logout:
   - POST /user/logout clears the cookie
   - Frontend removes token from localStorage
```

## 10. OTP Flow

```
Signup via OTP:
1. POST /otp/send    { phone, purpose: "signup" }
   → OTP generated, saved to DB, logged to console (TODO: send via SMS)
2. POST /otp/verify-signup
   { phone, code, fullName, username, email, password }
   → OTP verified, User created, tokens returned

Login via OTP:
1. POST /otp/send    { phone, purpose: "login" }
2. POST /otp/verify-login  { phone, code }
   → OTP verified, existing user authenticated, tokens returned

Security:
- Timing-safe comparison (crypto.timingSafeEqual)
- Max 3 verify attempts before OTP is invalidated
- Max 5 OTPs sent per hour per phone
- OTP auto-deleted via MongoDB TTL index after 5 minutes
- Rate limited: 10 sends / 15min, 20 verifies / 15min
```

## 14. Common Errors & Fixes

| Error | Cause | Fix |
|---|---|---|
| `querySrv ECONNREFUSED` | SRV DNS blocked on mobile hotspot | Use standard MongoDB URI (not `mongodb+srv://`) |
| `bad auth: authentication failed` | Wrong password in connection URI | Replace `<db_password>` placeholder with actual password |
| `Invalid scheme` | Multi-line URI in `.env` | Write the full URI on a single line |
| `Cannot find module 'bcrypt'` | Native `bcrypt` not compiled | Use `bcryptjs` instead (already installed) |
| `injecting env (3)` | 4th env variable not loaded | Check `.env` for missing newlines or BOM characters |
| `TokenExpiredError` | Access token expired | Call `POST /user/refresh` or redirect to `/auth` |
| `MulterError: File too large` | Image > 5MB | Compress image or raise Multer limit |
| `Cast to ObjectId failed` | Invalid ID in URL param | Validate `mongoose.isValidObjectId(id)` before querying |
| CORS error | `CLIENT_URL` mismatch | Set `CLIENT_URL` in backend `.env` to match exact frontend origin |
| Cookie not sent | Browser blocks cross-site cookies | Ensure `credentials: true` in Axios and `withCredentials: true` on frontend |
